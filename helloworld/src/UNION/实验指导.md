# 渗透问题实验指导

本实验来自《算法设计与分析》，目标是使用 Java、并查集和蒙特卡洛模拟，估计二维随机网格的渗透阈值。建议最终实现两个公开类：

- `Percolation`：维护一个 `N x N` 网格，支持打开格点、判断连通和判断是否渗透。
- `PercolationStats`：重复进行多次实验，计算平均阈值、标准差和 95% 置信区间。

`union.java` 当前只是一个空类，可以把它作为并查集练习入口；正式提交时应按照实验要求建立 `Percolation.java` 和 `PercolationStats.java`。

本指导解释设计思路和验证方法，不提供可直接提交的完整答案。建议先完成小规模手工测试，再进行统计实验；否则随机结果即使“看起来正常”，也可能掩盖连通方向或下标转换错误。

### 1. 推荐目录

如果沿用当前工程，建议文件结构如下：

```text
helloworld/
├─ lib/
│  └─ algs4.jar
├─ src/
│  └─ UNION/

```

`public class Percolation` 必须位于文件 `Percolation.java` 中，`PercolationStats` 同理。当前 `union.java` 不是实验要求的两个数据类型，不能只修改这个空类来代替它们。

如果源文件保留 `package UNION;`，两个实验类都必须声明相同的包，并且运行时使用完整类名 `UNION.PercolationStats`。如果课程提供的测试程序按默认包调用类，则删除包声明，并把源文件放在测试程序期望的源代码目录中；包声明必须与测试方式保持一致。

### 2. algs4 依赖与编译

本实验需要 `algs4.jar` 中的 `WeightedQuickUnionUF`、`StdRandom` 和 `StdStats`。先确认 jar 文件真实存在，再按当前工程的包声明编译。例如源文件位于 `src/UNION` 且保留 `package UNION;` 时，在 `helloworld` 目录执行：

```text

java -cp "bin;lib/algs4.jar" UNION.PercolationStats 20 30
```

Windows 的类路径分隔符是 `;`，macOS/Linux 是 `:`。若使用较旧的 algs4 版本，随机整数函数可能是 `StdRandom.uniform(int)` 而不是 `uniformInt(int)`；以本地 jar 的 API 为准，不要混用两套写法。

## 一、问题模型

网格中每个格点只有两种状态：

- `blocked`：阻塞，初始状态。
- `open`：开放，由 `open(row, col)` 改变。

一个开放格点是 `full`，当且仅当它能通过上、下、左、右四个方向的开放格点，连接到第一行的某个开放格点。只允许上下左右连接，不允许斜线连接。

如果底行存在一个 `full` 格点，系统就是 `percolates()`，即系统从顶部到底部连通。

实验通过不断随机打开尚未打开的格点，直到系统渗透。若最终打开了 `k` 个格点，则本次阈值估计为：

$$x = \frac{k}{N^2}$$

重复 `T` 次后，平均值就是对渗透阈值的估计。

## 二、需要掌握的 Java 知识

### 1. 类、对象和构造函数

```java
public class Percolation {
    private final int size;

    public Percolation(int n) {
        if (n <= 0) {
            throw new IllegalArgumentException("N must be positive");
        }
        size = n;
    }
}
```

- `class` 定义一种对象类型。
- `public` 表示其他包可以访问。
- 构造函数名称必须和类名相同，没有返回值。
- `private` 只允许类内部访问，用于封装实现细节。
- `final` 表示字段赋值后不再改变，适合保存网格大小。
- `this.size` 表示当前对象的字段，避免和参数混淆。

### 2. 字段与数组

二维网格可以使用：

```java
private boolean[][] open;
```

`open[row][col]` 保存格点状态，默认值是 `false`，正好代表 blocked。注意 Java 数组下标从 `0` 开始，而实验 API 的行列从 `1` 开始，因此必须转换：

```java
int rowIndex = row - 1;
int colIndex = col - 1;
```

数组大小为 `N * N`，因此初始化和存储空间都是 $O(N^2)$。

### 3. 布尔值、条件和异常

```java
if (!open[rowIndex][colIndex]) {
    open[rowIndex][colIndex] = true;
}
```

- `!`：逻辑非。
- `&&`：逻辑与。
- `||`：逻辑或。
- `boolean` 只有 `true` 和 `false`。

实验规定的异常：

```java
if (n <= 0) {
    throw new IllegalArgumentException();
}

if (row < 1 || row > size || col < 1 || col > size) {
    throw new IndexOutOfBoundsException();
}
```

构造函数使用 `IllegalArgumentException`；行列越界使用 `IndexOutOfBoundsException`。异常能让调用者明确知道输入不符合 API 约定。

### 4. 方法签名

实验 API 的签名必须准确：

```java
public void open(int row, int col)
public boolean isOpen(int row, int col)
public boolean isFull(int row, int col)
public boolean percolates()
```

- `void`：没有返回值。
- `boolean`：返回真假。
- 参数名可以不同，但参数类型、顺序和返回类型不能随意修改。
- `public` 方法构成类的外部接口，字段不应直接暴露。

### 5. `static`、`main` 和命令行参数

```java
public static void main(String[] args) {
    int n = Integer.parseInt(args[0]);
    int trials = Integer.parseInt(args[1]);
}
```

- `static` 方法属于类，不需要先创建对象。
- `main` 是 Java 程序入口。
- `String[] args` 保存命令行参数。
- `Integer.parseInt` 把字符串转换为 `int`。
- `Double.parseDouble` 把字符串转换为 `double`。

例如：

```text
java PercolationStats 200 100
```

此时 `args[0]` 是 `"200"`，`args[1]` 是 `"100"`。

### 6. `double`、整数除法和格式化输出

阈值必须使用 `double`：

```java
double threshold = (double) openCount / (size * size);
```

如果写成 `openCount / (size * size)`，两个操作数都是整数，会先进行整数除法，导致结果被截断。

输出可以使用：

```java
System.out.printf("mean                    = %.6f%n", stats.mean());
```

- `%.6f` 表示保留 6 位小数。
- `%n` 是跨平台换行。

### 7. 随机数和统计库

若使用 algs4：

```java
int row = StdRandom.uniformInt(1, size + 1);
int col = StdRandom.uniformInt(1, size + 1);
```

生成范围是左闭右开，即 `[1, size + 1)`，所以实际结果为 `1` 到 `size`。

统计量可以使用：

```java
double average = StdStats.mean(thresholds);
double deviation = StdStats.stddev(thresholds);
```

如果课程环境中的 algs4 版本较旧，随机数函数可能叫 `StdRandom.uniform(...)`；应以本地 `algs4.jar` 的 API 为准。

### 8. `main` 的输出契约

原实验 API 的方法名是 `confidenceLo()` 和 `confidenceHi()`，报告或程序中应统一使用这两个名字；不要把它们改成示例文字中偶尔出现的 `confidenceLow()` / `confidenceHigh()`。主函数应读取两个命令行参数 `N`、`T`，创建一次 `PercolationStats`，并至少输出均值、标准差和 95% 置信区间：

```text
mean                    = ...
stddev                  = ...
95% confidence interval = [..., ...]
```

输出小数位数可以自定，但标签和数值含义要清楚。参数缺失或不是整数属于命令行使用错误；构造函数仍必须对 `N <= 0` 或 `T <= 0` 抛出 `IllegalArgumentException`。

`T == 1` 是合法构造输入，但样本标准差的分母为 `T - 1`，因此 `StdStats.stddev` 的结果可能是 `NaN`。不要为了让输出好看而擅自把 `T == 1` 改成非法；报告中应说明该统计量在一次试验时没有定义。正式实验建议使用至少 30 次试验。

### 9. 随机实验的正确性边界

实验描述要求在所有 blocked 格点中均匀随机选择。不断生成随机坐标、遇到已打开格点就重试，最终得到的打开顺序仍是均匀的，但当网格接近全 open 时重试会变慢。更稳妥的替代方案是建立 `0` 到 `N*N-1` 的编号数组并随机打乱，然后按顺序打开；这会额外使用 $O(N^2)$ 空间，但不会重复抽样。

无论采用哪种方法，都必须用实际打开数量 `openCount` 计算阈值。不能用循环次数代替，因为随机坐标方法会产生重复位置。

## 三、并查集算法

### 1. 并查集解决什么问题

并查集（Union-Find）维护若干个不相交集合，主要支持：

- `find(p)`：找到元素 `p` 所属集合的代表元。
- `union(p, q)`：合并 `p` 和 `q` 所属的集合。
- `connected(p, q)`：判断两个元素是否属于同一集合。
- `count()`：集合数量。

本实验中，一个数组位置代表一个格点。两个相邻开放格点进行 `union` 后，就可以用 `connected` 判断它们是否属于同一连通区域。

### 2. Quick-Find

Quick-Find 使用 `id[i]` 表示元素 `i` 所属集合编号。

- `find(p)`：直接返回 `id[p]`，时间为 $O(1)$。
- `union(p, q)`：扫描整个数组，把属于 `p` 集合的元素改成 `q` 的集合编号。若并查集含有 $V$ 个元素，时间是 $O(V)$；本实验中 $V=N^2$（再加少量虚拟节点），不是把 $N^2$ 再平方。

优点是 `find` 快，缺点是大量合并时很慢。实验要求用它做性能对比。

### 3. Weighted Quick-Union

Weighted Quick-Union 用树表示集合，并保存每棵树的大小。合并时把较小的树连接到较大的树上，避免树变得过高。

加入路径压缩后：

```java
private int find(int value) {
    while (value != parent[value]) {
        parent[value] = parent[parent[value]];
        value = parent[value];
    }
    return value;
}
```

这一段会在查找过程中把节点直接提升到较浅的位置。仅按树大小加权时，树高为 $O(\log V)$；若同时采用路径压缩，`find` 和 `union` 的摊销复杂度才可严格写为 $O(\alpha(V))$，其中 $\alpha$ 是增长极慢的反阿克曼函数。使用 algs4 的 `WeightedQuickUnionUF` 时应检查本地版本是否包含路径压缩，并在报告中写清楚。

实验通常直接使用 algs4 的 `WeightedQuickUnionUF`：

```java
private final WeightedQuickUnionUF unionFind;
```

## 四、Percolation 的设计

### 1. 推荐字段

```java
private final int size;
private final boolean[][] open;
private final WeightedQuickUnionUF unionFind;
private final WeightedQuickUnionUF fullnessUnionFind;
private final int virtualTop;
private final int virtualBottom;
private int openCount;
```

索引策略：

- 网格格点编号为 `(row - 1) * size + (col - 1)`。
- 额外增加一个虚拟顶部节点 `virtualTop`。
- 为判断渗透，可以增加虚拟底部节点 `virtualBottom`。
- `unionFind` 用于判断系统是否渗透。
- `fullnessUnionFind` 只连接虚拟顶部，不连接虚拟底部，用于判断格点是否 full。

### 2. 为什么需要两个并查集：backwash

如果顶部和底部都连接到同一个并查集，那么系统渗透后，某些与底部相连但与顶部不相连的开放格点，可能因为虚拟底部节点而被错误判断为 full。这种错误称为 backwash。

正确方案：

- `unionFind`：顶部连接 `virtualTop`，底部连接 `virtualBottom`，用于 `percolates()`。
- `fullnessUnionFind`：只连接 `virtualTop`，不连接 `virtualBottom`，用于 `isFull()`。

这样既能快速判断顶部到底部是否连通，又不会让底部节点反向污染 full 判断。

不要通过“每次 `isFull` 都从顶部做 BFS/DFS”来绕开 backwash。那样逻辑上可以正确，但不满足题目要求的并查集常数次调用约束，而且会使 `isFull` 随网格规模线性变慢。

### 3. 一维编号函数

```java
private int index(int row, int col) {
    return (row - 1) * size + (col - 1);
}
```

例如 `size = 4` 时：

```text
(1, 1) -> 0
(1, 4) -> 3
(2, 1) -> 4
(4, 4) -> 15
```

并查集数组需要 `size * size + 2` 个位置，最后两个位置分别留给虚拟顶部和底部。

### 4. `open(row, col)` 的算法

步骤如下：

1. 检查行列是否在 `1..N`。
2. 如果已经 open，直接返回，不能重复增加 `openCount`。
3. 标记为 open，并令 `openCount++`。
4. 如果该格点在第一行，把它与 `virtualTop` 合并。
5. 如果该格点在最后一行，只在 `unionFind` 中与 `virtualBottom` 合并。
6. 检查上、下、左、右四个邻居。
7. 对于存在且 open 的邻居，在两个并查集中都执行合并。

可以用辅助方法减少重复代码：

```java
private void connectIfOpen(int row, int col, int neighborRow, int neighborCol) {
    if (neighborRow >= 1 && neighborRow <= size
            && neighborCol >= 1 && neighborCol <= size
            && isOpen(neighborRow, neighborCol)) {
        int current = index(row, col);
        int neighbor = index(neighborRow, neighborCol);
        unionFind.union(current, neighbor);
        fullnessUnionFind.union(current, neighbor);
    }
}
```

### 5. `isOpen(row, col)`

步骤：

1. 检查下标。
2. 返回 `open[row - 1][col - 1]`。

复杂度为 $O(1)$。

建议把下标检查集中到一个私有方法中，并在 `open`、`isOpen`、`isFull` 的最前面调用它。这样可以避免某个 API 方法漏掉边界检查。

### 6. `isFull(row, col)`

步骤：

1. 检查下标。
2. 如果格点 blocked，直接返回 `false`。
3. 判断 `fullnessUnionFind.connected(index(row, col), virtualTop)`。

这样可以避免遍历整个网格，平均性能取决于并查集实现。

### 7. `percolates()`

```java
public boolean percolates() {
    return unionFind.connected(virtualTop, virtualBottom);
}
```

特殊情况 `N = 1`：当唯一格点打开时，它既连接顶部也连接底部，因此系统渗透。

## 五、PercolationStats 的设计

### 1. 构造函数

```java
public PercolationStats(int n, int trials) {
    if (n <= 0 || trials <= 0) {
        throw new IllegalArgumentException();
    }
    // 进行 trials 次实验
}
```

每次实验都必须创建全新的 `Percolation` 对象，不能重复使用上一次实验的网格。

### 2. 单次实验流程

```text
创建全 blocked 的 Percolation
opened = 0
while 系统没有渗透:
    随机生成一行和一列
    如果该格点未打开:
        打开它
        opened++
记录 opened / (N * N)
```

随机位置可能重复，因此必须先判断 `isOpen`。如果重复打开仍然增加计数，阈值会错误地超过真实值。

更简单但可能效率较低的写法是重复随机生成直到选到 blocked 格点；也可以把所有格点编号放入数组后随机打乱，再依次打开，每个格点只访问一次。

### 3. 均值

设每次实验的阈值是 $x_1, x_2, ..., x_T$：

$$\mu = \frac{x_1+x_2+\cdots+x_T}{T}$$

保存所有阈值：

```java
private final double[] thresholds;
```

然后调用 `StdStats.mean(thresholds)`，或自行循环累加。

### 4. 样本标准差

$$
\sigma = \sqrt{\frac{\sum_{i=1}^{T}(x_i-\mu)^2}{T-1}}
$$

分母是 `T - 1`，不是 `T`，因为实验要求的是样本标准差。使用 algs4 时调用 `StdStats.stddev(thresholds)`。

当 `T == 1` 时，样本标准差没有通常意义；但实验只要求构造函数允许正数 `T`，应直接遵循课程库的行为，不要擅自改变 API。

### 5. 95% 置信区间

```java
public double confidenceLo() {
    return mean() - 1.96 * stddev() / Math.sqrt(trials);
}

public double confidenceHi() {
    return mean() + 1.96 * stddev() / Math.sqrt(trials);
}
```

这里用到：

- `Math.sqrt(x)`：平方根。
- `1.96`：正态近似下 95% 置信区间的系数。
- `Math.sqrt(trials)`：试验次数的平方根。

## 六、测试方案

### 1. 构造函数测试

- `new Percolation(0)` 应抛出 `IllegalArgumentException`。
- `new Percolation(-1)` 应抛出 `IllegalArgumentException`。
- 网格创建后所有格点都应为 blocked。

### 2. 下标测试

对 `open`、`isOpen`、`isFull` 分别测试：

- 行为 `0` 或 `N + 1`。
- 列为 `0` 或 `N + 1`。

都应抛出 `IndexOutOfBoundsException`。

### 3. 连通性测试

- 打开一个中间格点，它应是 open，但不是 full。
- 打开第一行格点，它应同时是 open 和 full。
- 依次打开一条从顶部到底部的路径，`percolates()` 应为 `true`。
- 打开对角线但没有上下左右连接时，系统不应渗透。
- 重复调用 `open` 不应增加 open 格点数量或破坏结果。

### 4. backwash 测试

在一个已经渗透的网格中，再打开一个只连接底部、但不连接顶部的格点。该格点必须：

```text
isOpen == true
isFull == false
```

如果它被判断为 full，说明错误地让 `isFull()` 使用了带虚拟底部的并查集。

### 5. 统计测试

- `new PercolationStats(0, 10)` 应抛出异常。
- `new PercolationStats(10, 0)` 应抛出异常。
- 所有阈值都应在 `(0, 1]` 范围内。
- `confidenceLo() <= mean() <= confidenceHi()`。
- 增大 `T` 后，统计结果通常更稳定，但随机实验不保证每次完全相同。

## 七、复杂度分析

设网格有 $V=N^2$ 个格点。

### Quick-Find

- 创建网格：$O(N^2)$。
- `isOpen`：$O(1)$。
- 一次 `open`：可能需要多次 `union`，每次 Quick-Find 的合并为 $O(V)$，因此最坏约为 $O(V)$。
- 一次实验最多打开 $V$ 个格点，因此最坏约为 $O(V^2)=O(N^4)$。
- `T` 次实验总时间近似为 $O(TN^4)$。
- 空间复杂度为 $O(N^2)$。

### Weighted Quick-Union

- 仅按树大小加权时，树高为 $O(\log V)$；若同时采用路径压缩，`find` 和 `union` 的摊销复杂度才可严格写为 $O(\alpha(V))$。使用 algs4 的 `WeightedQuickUnionUF` 时应检查本地版本是否包含路径压缩，并在报告中写清楚。
- 一次 `open` 只检查四个邻居，因此仅按树大小加权时为 $O(\log V)$；加上路径压缩时摊销为 $O(\alpha(V))$。
- 一次实验约为 $O(V\alpha(V))$。
- `T` 次实验约为 $O(TN^2\alpha(N^2))$，工程上通常近似认为接近 $O(TN^2)$。
- 空间复杂度为 $O(N^2)$。

当 `N` 加倍时：

- 网格格点数量变为原来的 4 倍。
- Quick-Find 的理论工作量约增长到原来的 16 倍。
- 仅按树大小加权的 Weighted Quick-Union 约增长为原来的 $4\log(4V)/\log V$ 倍；带路径压缩时通常接近 4 倍，但实际比例应由测量给出。

实际运行时间还会受到随机打开数量、Java 虚拟机、硬件和输入规模的影响，因此应多测几组数据后再用近似趋势描述。Quick-Find 的 $O(TN^4)$ 是最坏量级；实验在渗透后停止，通常不会打开全部 $N^2$ 个格点。

## 八、常见错误

1. 把实验的 1-based 行列直接当成 Java 数组的 0-based 下标。
2. 把斜线邻居也连接起来。
3. 重复调用 `open` 时重复增加计数。
4. 使用整数除法计算阈值。
5. `isFull()` 使用包含虚拟底部节点的并查集，导致 backwash。
6. 每次调用 `percolates()` 都遍历整个网格，导致性能不符合要求。
7. `PercolationStats` 的每一次试验复用同一个 `Percolation` 对象。
8. 样本标准差分母误写成 `T`。
9. 随机数上界写错，生成了 `0` 或 `N + 1`。
10. 类名、文件名和 `public class` 名称不一致。Java 中 `public class Percolation` 必须放在 `Percolation.java` 中。

## 九、建议实现顺序

1. 先实现并测试网格状态和下标检查。
2. 加入一维编号函数。
3. 加入一个并查集，完成 `open` 和 `percolates`。
4. 加入第二个并查集，修复 `isFull` 的 backwash。
5. 编写小规模手工测试，重点测试 `N = 1` 和边界格点。
6. 实现单次蒙特卡洛实验。
7. 实现 `PercolationStats` 和统计函数。
8. 使用 `N = 20, T = 30` 等较小参数检查输出，再测试较大参数。
9. 分别替换 Quick-Find 和 Weighted Quick-Union，记录 `N` 加倍时的运行时间。

## 十、报告中可以写出的结论

本实验将网格连通问题转换为并查集连通问题。虚拟顶部和虚拟底部节点使渗透判断可以由一次 `connected` 完成；两个并查集则解决了 `isFull` 的 backwash 问题。Quick-Find 的合并操作需要扫描整个并查集数组，网格规模增大时运行时间增长明显；Weighted Quick-Union 通过按树大小合并并结合路径压缩降低树高，在大规模实验中表现出更好的扩展性。蒙特卡洛实验的次数越多，样本均值通常越接近真实阈值，置信区间的宽度也通常会减小。

报告中的性能结论应由实测数据支持，不要只写“加倍后一定是 16 倍或 4 倍”。建议固定 `T`，分别测试 `N = 20, 40, 80, 160`，记录总耗时和平均耗时；每组至少运行两次并说明是否取平均。比较 Quick-Find 与 Weighted Quick-Union 时，应保持随机实验流程、JDK、机器和 `T` 完全一致，只替换并查集实现。
